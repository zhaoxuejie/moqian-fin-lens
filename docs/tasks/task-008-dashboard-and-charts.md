## 背景与目标

把已确认的 8 组图表落到真实页面与接口上：服务端渲染页面骨架，图表数据由 JSON 接口提供，前端用原生 JS + ECharts 渲染。视觉与交互以原型为准，但数据必须来自 TASK-006/007 的真实产物。

## 执行步骤

1. 页面路由：`GET /`（上传页占位）、`GET /s/{session_id}`（看板页）。
2. 看板数据接口：`/api/v1/sessions/{id}`、`/statements`、`/metrics`、`/charts`、`/anomalies`，字段严格按接口契约。
3. 8 组图表数据装配：V1～V7 由指标序列生成，V8 走异常项接口。
4. 前端渲染：指标卡、三表 Tab、8 图、溯源弹层、缺数据灰占位。
5. 单期降级：只有一期时，趋势类图表显示「需上传多期」，不画单点趋势。
6. 与原型逐区块比对布局与交互。

## 交付物

- `app/routes/dashboard.py` + Jinja 模板 + 静态 JS
- `dashboard/build.py`（图表数据装配）与接口实现
- 前端交互：Tab 切换、悬停、溯源弹层、缺数据占位
- 接口契约测试与页面快照

## 验收标准（布尔判定）

1. `GET /s/{id}` 渲染出基础信息、8 个指标卡与三表摘要，HTTP 200。
2. `/charts` 返回 v1～v7 且字段符合契约；v8 由 `/anomalies` 提供。
3. 8 组图表渲染的数据与 `/metrics` 一致（抽样比对，无前端重算）。
4. 缺数据时显示灰色「数据不足」占位，不画 0。
5. 单期会话下 V4 显示「需上传多期」。
6. 点击任一数字角标可打开溯源弹层，含页码、片段、口径。
7. 本地首屏渲染 ≤ 3 秒。

## 评测方案

- 契约测试：逐接口断言字段与枚举。
- 数据一致性：脚本比对图表 series 与 metrics 值。
- 人工验收：对照原型逐区块检查（布局、交互、占位文案）。
- 可访问性底线：键盘可切换 Tab，弹层可 Esc 关闭。

## 风险与备注

- 前端只做展示与格式化，任何聚合计算都在后端，避免「页面与导出口径不一致」。
- 图表库版本固定并自托管（ADR-002 的许可证原则同样适用于前端依赖）。
