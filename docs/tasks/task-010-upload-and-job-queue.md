## 背景与目标

当前会话只能由脚本构建，普通用户无法上传。本卡交付上传入口与后台解析任务：上传 → 排队 → 进度 → 完成跳看板，并落实文件校验、并发上限与失败反馈。

## 执行步骤

1. 首页改造：上传区（拖拽 / 选择），显示校验提示与免责声明。
2. `POST /api/v1/uploads`：校验类型（扩展名 + 文件头）、大小 ≤50MB、页数 ≤400；落临时目录；创建 session / filing / job 记录。
3. 任务状态机：`queued → parsing → aligning → computing → done/failed`，异步执行解析（复用 TASK-006～008 的构建函数）。
4. 进度接口 `GET /api/v1/jobs/{job_id}`：progress、stage、queue_position。
5. 失败处理：错误码 + 「哪一步、哪份文件、哪一页」，任务可重试。
6. 并发控制：全局 5 个解析任务，超出排队；单 IP 上传 10 次/小时。
7. 完成后跳转 `/s/{session_id}`。

## 交付物

- 上传页与交互脚本
- 上传 / 任务接口实现与任务执行器
- 校验与限流中间件
- 契约测试与真实上传端到端脚本

## 验收标准（布尔判定）

1. 上传一份合法年报返回 200，并在 60 秒内到达 `done`，页面可跳转看板。
2. 非 PDF、超过 50MB、超过 400 页分别返回 40001 / 40002 / 40003，且不残留临时文件。
3. 并发上传 6 份时第 6 份 `queue_position = 1`，前 5 份并行解析。
4. 解析失败返回 42201 且带页码与阶段；重试后成功。
5. 单 IP 一小时内第 11 次上传返回 42901 并带 `Retry-After`。
6. 上传完成的会话可直接访问 `/s/{id}`，页面数据与脚本构建结果一致。

## 评测方案

- 契约测试：上传、进度、限流、错误码。
- 端到端：真实年报上传 → 轮询 → 看板，记录总耗时。
- 负样本：非 PDF、超大文件、超页数、损坏 PDF 各 1 份。

## 风险与备注

- 解析耗时与 60 秒门槛：真实 300 页报告构建约 5 秒，余量充足；但并发 5 份时需观察内存。
- 本卡不落库会话（TASK-012 负责持久化），进程重启任务丢失属已知限制。
