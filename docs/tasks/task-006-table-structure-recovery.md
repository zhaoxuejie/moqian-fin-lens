## 背景与目标

TASK-002～005 用「行首取标签」的近似法验证了链路，但没法回答「这个数字属于哪一行、哪一列、在第几页的什么位置」。本卡把三表页还原成真正的单元格结构：**科目行 × 期间列 × 单元格（数值 / 页码 / 原文片段 / bbox）**，为指标计算与溯源提供干净输入。

## 执行步骤

1. 表格区域检测：按文本块坐标聚类，识别三表页的表格上下边界与左右边界。
2. 行还原：同一 y 带内的文本块合并为一行；识别并处理合并单元格（跨行标题、跨列小计）。
3. 列还原：依据表头文字识别期间列（本期 / 上期 / 年初 / 上年年末），映射为 `period`。
4. 跨页拼接：表尾无「合计」行且下一页列头重复时视为续表，拼接为一条表；记录每行原始页码。
5. 单元格绑定：单元格文本 → `parse.normalize` → 数值；同时保留原文片段与 bbox。
6. 输出 `StatementRow`：`account_label / period / value / page / snippet / bbox / is_missing`。
7. 评估集新增「行-值」金标：10 份年报 × 20 行 = 200 行。

## 交付物

- `parse/table.py`：表格检测、行列还原、跨页拼接
- `StatementRow` 数据结构与单测
- `tests/eval/gold/table-200.json` 与逐行比对脚本
- 未对齐清单增加「行级」粒度（哪一行还原失败、哪一页）

## 验收标准（布尔判定）

1. 三表每个还原出的单元格都带页码与原文片段（缺一即失败）。
2. 金标 200 行逐行一致率 ≥ 95%（科目名 + 两期数值）。
3. 跨页表样例：拼接后的行数与金标一致，且不出现重复行。
4. 合并单元格不串行：人工抽检 50 行通过（数字与科目对应正确）。
5. 空值单元格 `is_missing=true`，不输出 0。
6. 单份 300 页年报的表格还原耗时 ≤ 60 秒。

## 评测方案

- 逐行比对脚本：金标行 → 实际行 → 允许 ±2 行偏移，比较科目名与数值。
- 人工抽检：随机 5 份报告各 10 行，核对科目与数字。
- 负样本：无边框表、斜线表头各 1 份，验证失败时给出明确原因而非错行。
