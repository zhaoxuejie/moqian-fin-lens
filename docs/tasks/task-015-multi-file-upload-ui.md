# TASK-015 多文件上传与继续上传

- 里程碑：v1.0（体验补漏）
- 前置依赖：TASK-011
- 优先级：P1
- 状态：✅ done（2026-11-01 验收通过）
- 来源：v0.2.0 试用反馈（多期后端已支持，页面无入口）
- 关联文档：`docs/tasks/task-011-multi-period-sessions.md`

## 背景与目标

后端 `POST /uploads` 已支持带 `session_id` 续传（TASK-011），但页面上只能单文件上传，多期只能靠接口调用。本卡把入口补进页面：首页一次可选多份同一公司年报，看板页可继续上传，错误有明确提示。

## 执行步骤

1. 首页文件框改为多选（`multiple`），提示「同一公司最多 5 期」。
2. 前端按顺序上传：第一份拿 `session_id`，其余带 `session_id` 续传；逐份显示进度。
3. 任一份失败即停止后续上传，显示后端错误（公司不一致 / 期间重复 / 超期数）。
4. 全部完成后跳转看板；部分失败时停在首页并保留已成功的会话链接。
5. 看板页增加「继续上传」按钮：单文件、带当前 `session_id`，完成后刷新。
6. 页面文案与按钮状态（上传中禁用）处理。

## 交付物

- 首页多选上传与顺序编排脚本
- 看板「继续上传」按钮与脚本
- 错误提示与状态管理
- 页面结构测试（`multiple`、按钮存在）

## 验收标准（布尔判定）

1. 首页一次选择 2 份同公司年报，依次上传成功，看板 `filing_count = 2`、图表 x 轴两期。
2. 一次选择 3 份时报文（评估集仅两年）不适用，改为：选 2 份后在看板「继续上传」第 3 期（若数据存在），或接口层已由 TASK-011 覆盖。
3. 选择不同公司年报时，第二份上传被拒绝并显示「与已有会话不是同一公司」，已成功的会话仍可访问。
4. 同一期间重复上传时提示「报告期已存在」。
5. 上传过程中按钮禁用，失败后恢复可用。
6. 页面源码包含 `multiple` 属性与「继续上传」按钮（自动化断言）。

## 评测方案

- 页面结构断言：GET / 含 `multiple`；GET /s/{id} 含「继续上传」。
- 交互人工验收：真实上传 2 期 + 继续上传 1 次失败样本。
- 接口层回归：TASK-011 的 4 项集成测试保持通过。

## 风险与备注

- 多年份文件体积大时上传耗时，需显示逐份进度；本卡不做并发上传（顺序更可控）。
- 期数上限以服务端 `max_filings_per_session` 为准，前端只做提示不做拦截。
