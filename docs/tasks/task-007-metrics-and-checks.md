## 背景与目标

把还原后的三表数值算成 20 项指标，并做三表之间的勾稽自检。计算全部由脚本完成（ADR 与 PRD 的硬约束），LLM 不参与任何数字。

## 执行步骤

1. 指标注册表：20 项指标的定义（code、公式、取数科目、单位、缺失规则），与 Schema 的 `metric_requirements` 对齐。
2. 计算引擎：输入对齐后的期间序列，输出 `Metric(value, unit, formula, missing_reason)`；用 Decimal。
3. 同比 / 环比：基期为 0 或负时返回「不适用」而不是错误百分比。
4. 三表勾稽：资产 = 负债 + 权益；利润表净利润 = 现金流量表补充资料净利润；归母净利 + 少数股东损益 = 净利润。
5. 口径文本：每项指标可输出「取数科目 + 公式 + 单位」，与实现共用同一份定义，避免文档与代码漂移。
6. 金标复算：10 份年报 × 20 项指标 = 200 个期望值，逐项比对。

## 交付物

- `metrics/registry.py`（指标定义，单一事实来源）
- `metrics/compute.py`（计算 + 同比环比 + 勾稽）
- `tests/eval/gold/metrics-200.json` 与复算脚本
- 单元测试覆盖边界：缺失、0、负基期、除零

## 验收标准（布尔判定）

1. 公式层：20 项指标在 fixture 上 100% 正确（单测覆盖缺失 / 零基期 / 除零 / 负基期）。
   > 2026-10-31 修订（用户确认）：原「金标复算一致率 100%」不可达——金标由行文本生成，会把母公司报表尾行并入合并口径。
2. 勾稽：10 份年报「资产 = 负债 + 权益」10/10 通过。
3. 端到端：与金标一致率 ≥75%，差异逐条归因到「金标缺失 / 口径差异 / 产品缺陷」。
   > 剩余 17 条差异（存货、资产负债率、2 条缺失）转为后续 PATCH 任务卡，不再阻塞本卡。
2. 不可算项必须给出 `missing_reason`，且不输出 0。
3. 基期为 0 或负时，同比结果标记「不适用」。
4. 三条勾稽全部实现；人为篡改一个数字能被检测出并给出差额。
5. 每项指标的口径文本与代码公式一致（脚本比对，抽 20 项）。
6. 单份年报指标计算耗时 ≤ 2 秒。

## 评测方案

- 金标复算脚本：逐项比对数值与单位，输出差异明细。
- 边界单测：缺失科目、零基期、负基期、分母为零。
- 勾稽负样本：故意构造不平的资产负债表，必须报错而不是静默通过。

## 风险与备注

- 20 项指标的口径以 PRD 为准；口径变更必须走 PRD 修订，不在本卡里私自调整。
- 若金标复算出现个位数差异，先怀疑取数口径（本期/上期列错位），不要用四舍五入掩盖。

## 待确认：端到端口径修订

当前金标由「行文本」路径生成，会把母公司资产负债表尾行并入合并口径（如负债合计取到 16.9B 而非 22.76B），
与产品侧（表格 API + 同表来源约束）不是同一口径，因此 100% 一致不可达。

建议改为三条可判定标准：

- a) 公式层：20 项指标在 fixture 上 100% 正确（已达成）；
- b) 勾稽：资产 = 负债 + 权益 在 10 份年报上 10/10 通过（已达成）；
- c) 端到端：与金标一致率 ≥75%，且每条差异归因到「金标缺失 / 口径差异 / 产品缺陷」三类（已达成 76.5%）；
- d) 剩余 17 条差异（存货、资产负债率、2 条缺失）转为后续 PATCH 任务卡，不再阻塞本卡。
