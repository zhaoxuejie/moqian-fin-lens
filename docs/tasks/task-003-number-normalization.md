## 背景与目标

财报里的数字不是「干净的 float」：有千分位、有括号负数、有「—」表示无数据、有「万元/亿元」混排、有「不适用」。这一层做错，后面 99% 一致率永远达不到。本卡只做数值归一，不做科目映射。

## 执行步骤

1. 实现 `parse.normalize(value_text, unit_hint)`，返回 `{value, unit, sign, is_missing}`。
2. 处理千分位 `,`、全角符号、不间断空格。
3. 处理负数：括号 `(1,234.00)`、`－`、`-`、`—` 分别定义语义（括号与其他负号均为负；`—`、`-`、`不适用`、空白为缺失）。
4. 处理单位：元 / 万元 / 亿元 / 百分比；统一换算为元，使用 `Decimal`，禁止 float 累加。
5. 处理小数位与精度规则（金额两位、百分比两位）。
6. 非法输入抛业务异常（不返回猜测值），异常信息含原文片段。

## 交付物

- `parse/normalize.py` 实现与单元测试
- 数值格式规则说明（写进 `parse/README.md` 或代码注释）
- 金标 100 个数字的比对脚本与结果

## 验收标准（布尔判定）

1. 单测 ≥ 40 条，覆盖千分位、括号负数、`－`、`—`、空白、`不适用`、万元、亿元、百分比、全角数字，全绿。
2. 空值输入输出 `value=None` 且 `is_missing=true`，绝不输出 0。
3. 单位换算误差为 0：`1.2345 亿元` 与 `Decimal("123450000")` 精确相等。
4. 金标 100 个数字（含跨页表数字）比对一致率 100%。
5. 非法输入（如 `abc`、`--`）抛出业务异常码，不返回 `0` 或 `NaN`。
6. 同一输入重复调用结果一致（纯函数，无状态）。

## 评测方案

- 单元测试：按格式维度参数化，断言 `value`、`unit`、`is_missing` 三元组。
- 金标比对：读取评估集金标数字 → 走归一 → 精确比较 → 输出不一致明细。
- 回归：所有失败样例进 `tests/unit/normalize_cases/`，后续改动必须全绿。

## 风险与备注

- 破折号的语义在不同公司不同：`—` 有时表示 0，有时表示未披露。本卡按「未披露」处理并在文档写明；如评估集证伪，需更新本卡验收标准而不是放宽逻辑。
- 若原文用「(1,234)」表示负数但同表存在真正的括号注释，需依赖上下文列位置判断，属于后续表格还原范畴，不在本卡范围。
