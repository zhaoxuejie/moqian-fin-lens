# prompt.md
> 本文件：【陌阡AI工程治理框架全局启动提示词模板】
> 使用时机：开启一轮全新对话、让AI接手本项目工作时，**全文粘贴给AI**
> 作用：告知AI整套流程、目录、约束、工作模式，强制遵守框架；仅作为会话启动文案，不交给AI在开发中自动读取（开发过程中的运行约束在 AGENTS.md）

---

你现在需要严格遵守我固定的 **陌阡AI工程治理框架**，所有项目、所有迭代、所有开发行为必须 100% 遵从以下规范，禁止私自变更、禁止简化流程、禁止一次性全量生成、禁止跳过文档、禁止跳过任务卡、禁止跳过评测。

## 1. 固定仓库目录结构（强制）
所有项目统一结构，严格大小写规范：
- 根目录顶层文件：首字母大写：README.md、AGENTS.md、CONTRIBUTING.md、CHANGELOG.md
- docs 目录内文档统一小写 kebab-case
- 任务卡模式：**一个任务单独一个文件**

```
moqian-ai-template/
├── README.md
├── AGENTS.md
├── CONTRIBUTING.md
├── CHANGELOG.md
├── .env.example
├── docs/
│   ├── readme.md
│   ├── prompt.md
│   ├── stage-prompts.md
│   ├── prd.md
│   ├── architecture.md
│   ├── api-contract.md
│   ├── archive/
│   └── tasks/
│       ├── readme.md
│       └── task-00x-xxx.md
├── scripts/
├── tests/
└── .github/workflows/
```

## 2. 文档迭代规则（强制）
1. 先文档、后代码：需求、架构、接口文档没有落地确认前，禁止编写业务代码。
2. 版本升级规范
   - MAJOR 破坏性升级：先归档快照到 `docs/archive/vX.Y/`，再更新当前活跃文档
   - MINOR / PATCH 兼容迭代：直接修改当前文档，不操作 archive，不复制快照
3. ADR 决策只追加、不修改、不删除历史已接受的ADR
4. 废弃接口、废弃功能不能直接删除，必须标记 deprecated，附带迁移指引

## 3. 任务卡执行规则（核心约束）
1. 所有开发任务拆分为独立单文件任务卡，命名 `task-00N-short-description.md`
2. **禁止一次性全量拆解整个里程碑所有任务**，采用增量拆分：完成一批、人工确认后，再拆解下一批
3. 每张任务卡必须包含：唯一编号 TASK-00X、前置依赖、优先级、可验收标准（布尔判定）、评测方案
4. 前置依赖状态不为 done 的任务，禁止启动开发
5. 任务必须完成验收、通过评测，才可以标记为 done

## 4. AI 工作模式（强制）
1. 不自行新增范围外的功能
2. 不跳过流程、简化文档、省略评测环节
3. 开工前先查阅当前文档、tasks/readme.md 任务索引，识别可执行任务
4. 只处理【前置依赖全部 done】的任务，不提前开发未来任务

## 5. 新项目 0→1 固定顺序
1. 生成项目骨架目录
2. 完善根目录 README.md、AGENTS.md、CONTRIBUTING.md
3. 编写 prd.md，确定范围、里程碑
4. 编写 architecture.md，架构方案 + ADR
5. 编写 api-contract.md 接口契约
6. 增量输出第一批顶层任务卡（建议3～5张以内）
7. 人工审阅确认任务卡，录入 tasks、更新索引表
8. 按依赖顺序开发、验收、评测、标记 done
9. 基于已完成任务，继续增量拆解后续任务
10. 里程碑全部完成，执行发布脚本，打tag、更新 CHANGELOG.md

## 6. MAJOR版本迭代升级流程（如 v1.0 → v2.0）
1. 归档当前稳定全套文档快照至 docs/archive/v1.0/
2. 更新 prd.md / architecture.md / api-contract.md
3. 在 architecture.md 新增ADR记录本次升级决策、取舍、风险
4. 增量生成升级相关任务卡
5. 逐任务开发、验收、评测回归
6. 版本就绪，打tag、更新 CHANGELOG

## 7. 回复输出约定
每次输出尽量包含：
1. 当前进度总结
2. 当前可执行任务清单（仅前置依赖全部 done 的）
3. 本次产出物（文档/任务卡/代码）
4. 下一步可执行计划

## 8. 永久禁止行为
- 禁止一次性批量生成全部任务卡
- 禁止无文档直接写业务代码
- 禁止修改、删除历史ADR，禁止修改archive内冻结快照
- 禁止跳过验收、跳过评测
- 禁止同时并行开发多个未确认任务
- 禁止人为打乱任务依赖顺序

> 从本次对话开始，全程遵循陌阡AI工程治理体系，不再自行简化流程。
