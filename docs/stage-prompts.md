# stage-prompts.md
> 使用方式：
> 1. 新开会话：先粘贴 docs/prompt.md（框架基座规则）
> 2. 再挑选下面对应阶段的指令，追加发给AI
> 3. 一个阶段做完，再换下一个阶段指令；不要一次性全部发给AI

## 阶段0：初始化项目骨架（新建项目第一件事）
> 适用：项目刚启动，还没有任何文件
```
请基于本工程框架，输出完整的项目骨架目录和初始文件内容，严格遵循目录规范、命名规范。
初始产出：README.md、AGENTS.md、CONTRIBUTING.md、CHANGELOG.md、.env.example、docs/readme.md、docs/prompt.md、docs/stage-prompts.md、空的prd.md、architecture.md、api-contract.md、docs/tasks/readme.md、空archive目录。
不要写业务代码，只输出框架骨架。骨架生成完成后通知我，等待我给出项目需求，再进入PRD阶段。
```

## 阶段1：编写 PRD（需求阶段）
> 适用：骨架已经建好，我给你项目需求，输出 prd.md
```
现在进入PRD编写阶段。
请按照框架内 prd.md 的模板规范输出内容。
需要包含：项目目标、业务范围 In / Out、用户场景、功能清单、非功能需求、版本里程碑、版本变更摘要预留区、废弃清单预留区。
现阶段只产出 prd.md，**不做架构、不拆任务、不写代码**。
PRD初稿完成后交给我审阅，我确认通过之后，才可以进入架构阶段。
如果范围有模糊点，主动向我提问澄清，不要自行脑补需求。
```

## 阶段2：编写 Architecture + ADR（架构设计阶段）
> 适用：PRD已经我确认通过
```
现在进入架构设计阶段。
参考已确认的 prd.md，按照框架 architecture.md 模板输出架构方案。
需要包含：总体架构图文字描述、模块划分、数据流、依赖关系、技术选型、约束、风险，并且使用ADR记录关键决策。
ADR只追加，每个决策独立一条，写明上下文、备选方案、最终决策、取舍、风险。
现阶段只产出 architecture.md，不生成接口契约、不拆任务、不写代码。
架构初稿完成后交给我审阅，我确认通过，才可以进入api-contract阶段。
```

## 阶段3：编写 api-contract.md（接口契约阶段）
> 适用：架构文档我确认通过
```
现在进入接口契约阶段。
基于 prd.md 和 architecture.md，按照 api-contract.md 模板输出接口定义。
包含接口路径、请求参数、响应体、错误码、版本标记、deprecated预留字段、迁移指引预留。
现阶段只产出 api-contract.md，不拆分任务、不写代码。
接口文档初稿完成交给我审阅，我确认通过，才可以开始增量拆解任务卡。
```

## 阶段4：增量拆解任务卡（最核心，防止一次性炸一堆任务）
> 适用：PRD/架构/接口全部确认完毕，准备拆任务
```
现在进入任务拆分阶段。
遵循增量拆分规则：禁止一次性拆完全部里程碑任务。
先输出【顶层第一批任务】，控制在3～5个以内。
每张任务卡严格使用 task-00x-xxx.md 模板，包含：编号、里程碑、前置依赖、优先级、来源、执行步骤、验收标准、评测方案。
输出任务卡草稿之后，等待我人工审阅、修改确认。
我确认这批任务入库、更新 tasks/readme.md 索引之后，才可以开始开发，或者继续拆解下一批任务。
```

## 阶段5：开发单个任务卡（开发阶段）
> 适用：选中某一张前置依赖全部 done 的任务，开始编码
```
现在进入开发阶段，只处理 TASK-{{编号}} 这一张任务卡。
严格以这张任务卡的【验收标准】和【评测方案】作为唯一目标。
开发完成后，输出代码、配套测试用例，并且对照验收标准做自检说明。
产出完成后，等待我执行评测验收；评测不通过，继续修复，直到全部验收项满足。
本任务验收标记 done 之后，我们再看是否继续拆解后续任务或者开发下一个任务。
禁止主动开发其他任务。
```

## 阶段6：MAJOR版本升级（v1→v2，破坏性迭代）
> 适用：要做大版本不兼容升级
```
现在进入MAJOR版本升级流程。
第一步：先把当前稳定版全套docs（含tasks）复制归档到 docs/archive/{{旧版本号}}，生成快照commit提示。
第二步：更新 prd.md、architecture.md、api-contract.md，填写版本变更摘要、废弃清单、迁移指引。
第三步：在 architecture.md 新增一条ADR，记录本次升级的决策、取舍、风险。
第四步：增量生成升级相关任务卡，同样分批、不一次性全部拆完。
所有流程严格遵守框架版本归档规则。
```

## 阶段7：版本发布 & 打tag
> 适用：当前里程碑全部任务done，准备发布
```
当前里程碑所有任务已经验收完成，进入版本发布流程。
整理本次版本变更，更新 CHANGELOG.md，然后输出执行 scripts/release.sh 的指引，打好对应版本git tag。
发布完成后，同步更新文档头部版本号。
```

## 阶段8：评审 / 改错（通用，随时可用）
```
现在进入评审修正模式。
我会指出当前文档/任务卡/代码的问题。你只针对指出的问题做修正，不扩大范围、不新增额外功能、不额外拆解新任务。
修改完成后，列出改动点清单，等待我再次确认。
```
